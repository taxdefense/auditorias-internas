## Convenciones de este repositorio

Para cualquier sesión futura (con o sin la skill `auditoria-consolidada-marketing-360`) que agregue o actualice documentos aquí:

- **IDs de documento (`DOC-XX`):** se usan dentro de `consolidado/auditoria-consolidada-marketing-360.md` para trazabilidad. Nunca reutilices un número ya asignado — continúa la numeración (el máximo actual está en la tabla de inventario de ese archivo, sección 4).
- **IDs de tarea por backlog:** cada backlog tiene su propio prefijo — `TASK-` (consolidado y backlog maestro), `SL` (SEO/Landing), `G` (GA4), `T`+`A` (Investigación 2, tareas y activos), `WP-` (WordPress). Al fusionar backlogs en el maestro, las tareas migradas desde otro backlog NUNCA cambian de contenido/prioridad sin justificación — solo obtienen un nuevo `TASK-XXX` continuando la numeración del maestro, citando el ID original en "Coincidencias entre documentos" u "Observaciones".
- **`consolidado/backlog-maestro-clickup.csv` es la fuente operativa recomendada** para ClickUp/Notion/Excel de aquí en adelante. Los backlogs individuales (`seo/backlog-clickup-seo-landing.md`, `campanas-ads/backlog-clickup-ga4.md`, etc.) siguen vigentes como fuente de detalle por área y no se eliminan — el maestro los fusiona sin duplicar, no los reemplaza.
- **Notas fechadas entre paréntesis** (`*(Ajuste DD-MM-AAAA: ...)*`) son el patrón de este repo para registrar cambios sin reescribir silenciosamente lo anterior — úsalo tanto en este README como dentro de los documentos largos (ver `auditoria-consolidada-marketing-360.md`, que además numera sus notas de actualización como 1.1, 1.2, etc.).
- **`descargables/`** espeja en Word/Excel/CSV cada documento fuente en Markdown/CSV — cuando actualices un `.md` o `.csv`, regenera también su versión en `descargables/` (scripts en `.claude/skills/auditoria-consolidada-marketing-360/scripts/`: `generar_docx.py`, `generar_docx_tabla_oficio.py`, `generar_excel.py`, `generar_csv_notion.py`). Nunca compongas un CSV de backlog escribiendo texto a mano — usa `csv.writer` (ver `references/entregables-multiformato.md` de esa skill para el porqué).
- **No confundir este repo con `taxdefense/centro-editorial-ddc`** (tablero de contenidos del blog Jurídicamente, otro proyecto) — este repo es solo la auditoría técnica/marketing para el traspaso de la presencia digital.
